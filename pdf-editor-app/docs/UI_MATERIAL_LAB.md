# UI Material Lab 사용법 및 AI 작성 지침

업데이트: 2026-10-16 · 앱 v1.8.0

## 테마와 설정 글자 대비

설정은 `Alt+D`로 엽니다. PDF 편집기 꾸미기의 옵션 제목·값·안내는 카드의 실제 배경을 기준으로 밝거나 어두운 글자색을 선택합니다. 반투명 카드는 부모 배경과 합성한 색으로 판단하며, 버튼·입력창은 각 재질의 글자색을 유지합니다. 필기 텍스트의 사용자가 지정한 색은 UI 재질로 덮지 않습니다.

## 시작하기

플러그인 목록에서 UI Material Lab을 활성화하고 실행합니다. AI 코파일럿에서 선택한 제공자·모델·API 키를 사용합니다. 이전 Stitch MCP 연결·전용 키·SDK는 현재 생성 경로에서 제거했습니다.

1. 내장 Gradient UI Kit 프리셋을 불러오거나 [Magnific UI/UX 참고 사이트](https://www.magnific.com/kr/free-photos-vectors/ui-ux)에서 원하는 샘플을 내려받습니다. 앱의 링크는 웹 서퍼로 연결됩니다.
2. 이미지 한 장은 파일 선택 또는 Ctrl+V로, 여러 자료는 압축을 푼 뒤 폴더 선택으로 불러옵니다.
3. 버튼 형태·색상·배치 등 요청을 입력해 AI 디자인을 생성합니다. 생성·다시 만들기·디테일 수정은 API 사용량을 사용하며 중단할 수 있습니다. 패널을 닫아도 전역 생성 작업은 계속됩니다.
4. 편집기 재질 디자인 또는 버튼 UI 키트 디자인 카드를 선택합니다. 호버·키보드 초점에서 선택 버튼과 테두리를 강조하며, 선택만으로 실제 UI를 변경하지 않습니다.
5. 전체 편집기에 적용 또는 미리보기 창의 이 UI 적용을 누릅니다. 저장과 스타일시트 갱신을 같은 클릭에서 수행합니다. 적용 여부는 패널에 표시됩니다.

## 참고 자료 분석

파일/폴더 선택은 원문을 전송하지 않습니다. 생성 요청 때 선택한 제공자로 지원 자료를 순차 전달합니다. 이미지 입력을 지원하는 모델이 필요합니다.

| 형식 | 읽는 내용 |
| --- | --- |
| PNG/JPEG/WebP/BMP | 긴 변 최대 1600px 이미지로 형태·배치·버튼 상태 분석 |
| PDF, PDF 호환 AI | 모든 페이지를 렌더링해 분석. PDF 호환이 아닌 AI는 제외 |
| TXT/MD/JSON/CSS/SVG/EPS | 전체 텍스트를 조각으로 나눠 분석. 코드는 실행하지 않음 |
| 기타 | 제외 사유 표시 |

하위 폴더의 파일 목록과 파일별 진행·완료·실패·제외 내역을 표시합니다. EPS는 소스 분석이며 렌더링된 이미지를 보았다고 표현하지 않습니다. 폴더는 최대 100파일·합계 100MB, 파일당 20MB, 텍스트/EPS 2MB, PDF/AI 50페이지를 지원합니다. 축소 이미지의 작은 글자는 인식이 제한될 수 있습니다. 비용은 파일·페이지·텍스트 조각별 요청 수에 따라 달라집니다.

## 두 적용 방식과 영역별 조절

- `appearanceMode: materials`: workspace/panels/buttons/tools/inputs/settings의 재질을 그대로 적용합니다. 버튼 키트 상태가 사용자 지정 버튼색을 덮지 않습니다.
- `appearanceMode: kit`: 일반 버튼은 `buttonStates`, 도구 버튼은 `toolButtonStates`의 일반·선택·보조 선택·강조·비활성 상태를 적용합니다. 도구 상태가 없으면 일반 버튼 상태를 재사용하며, 도구 영역을 수정하면 독립 상태를 생성합니다.
- `buttonVariant: teal|purple`: 청록 또는 보라 선택 상태를 매핑합니다. 편집기의 논리적 선택 상태와 재질 다듬기의 선택 상태를 같은 기준으로 처리합니다.
- 현재 적용 중인 디자인을 다듬으면 선택한 영역만 즉시 변경하고 저장합니다. 적용하지 않은 새 초안은 미리보기만 변경하며 적용 버튼으로 반영합니다.
- 열린 상단 탭은 `aria-pressed`로 상태를 표시하고 별도 배경·굵은 테두리·밑줄로 비활성 탭과 구분합니다.

## 적용 해제와 보관

적용 해제는 재질 스타일을 제거하고 기본 반투명 테마, 사용자 배경색 기본값, 강조색, 모서리, 버튼 크기·간격, 테두리·그림자를 복구합니다. 저장된 AI 디자인을 지우지 않습니다. 이전 디자인 복구와 적용된 디자인 불러오기를 제공합니다.

AI 생성·디테일 수정·AI 도구 적용 결과는 보관함에 자동 저장합니다. 직접 다듬은 초안은 현재 초안 보관으로 저장합니다. 이름·시각·제공자·모델·요청과 함께 검색, 불러오기, 이름 변경, 삭제를 지원합니다. 적용 방식과 버튼 변형도 함께 보존합니다.

| 저장 키 | 내용 |
| --- | --- |
| `uiMaterialLab.v1` | 적용 재질·적용 여부 |
| `materialLab.draft.v1` | 최신 초안 |
| `materialLab.library.v1` | 디자인 보관함 |
| `editorUiDesign.v1` | 설정의 수동 UI 디테일 |

## 외부 AI 작성 규칙

`material_get`으로 실제 예시를 읽고 `material_apply({design})`에 완전한 디자인을 전달합니다. root 키는 name,materials,buttonStates?,toolButtonStates?,buttonVariant?,appearanceMode?입니다. name은 80자 이내이며 materials의 6개 영역을 모두 작성합니다.

재질 값은 fill/end/border(#RRGGBB),gradient(boolean),angle(0~360),radius(0~40),borderWidth(0~4),shadow(0~24),opacity(0.8~1)입니다. 버튼 상태 객체는 normal/selected/secondary/highlight/disabled를 모두 포함합니다. 임의 CSS·HTML·JS·URL을 재질에 넣지 않습니다. 디테일 수정 때 선택된 적용 방식과 도구 전용 상태를 보존하고 요청한 영역만 바꿉니다.

한글 가독성과 색상 대비를 먼저 고려합니다. 배경과 투명도에 맞춰 전경색을 계산하며 밝은 고정 표면은 독립적인 색상 기준을 갖습니다. 네이티브 드롭다운에는 불투명 배경·글자색·색상 모드를 지정합니다. 한글 대체 글꼴을 제공하고 필기 색상 견본은 전역 버튼 재질에서 제외합니다. PDF 본문·필기와 디자인 평가용 미리보기/스튜디오 컨트롤을 전역 재질로 덮지 않습니다.

## 검증

`npm run verify`는 타입·핵심 기능·PDF·Electron UI·플러그인·사용자 AI 제공자·빌드를 검사합니다. `npm run test:material-references`는 파일/폴더 선택과 이미지 어댑터를 모의 AI로 검사합니다. `MATERIAL_REFERENCE_FOLDER`를 지정하면 실제 참고 폴더도 검사합니다. 실제 유료 AI 응답 품질을 검증하는 명령은 아닙니다.
