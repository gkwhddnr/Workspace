# 새 JS 플러그인의 기본 작업 환경

기준: Workspace Pro 1.8.0 · 2026-10-16. 사용자가 더 단순한 기능을 요청하면 필요한 부분만 구현하되, 문서·AI 결과를 다루는 화면형 플러그인은 아래 구조를 기본으로 삼습니다.

## 참고 구현과 이식 범위

| 참고 | 새 플러그인에 가져올 구조 | 그대로 복사하지 않을 부분 |
| --- | --- | --- |
| Editorial Diagram 1.8.1 (`docs/examples/editorial-diagram.js`) | 단일 `registerPlugin`, 공개 AI 도구와 공통 작업 함수, 현재 파일·페이지 문맥, 실제 본문 처리, 파일·페이지별 저장, 저장 결과 재사용, 자동 처리와 명시적 갱신, SVG 미리보기·맞춤·확대·내보내기 | Editorial 전용 ID·저장 키·요약 문구·노드 도식 및 과거 예제의 구현상 우연 |
| UI Material Lab 2.0.0 (`uiDesign.ts`, `MaterialLabPanel.tsx`, `MaterialLabService.ts`, 재질 모델·스토어) | 입력/참고 자료 → 실행·중단·진행 상태 → 초안 → 미리보기·선택 → 적용/다시 만들기/디테일 수정 → 보관함·복구. 검증·작업 상태·렌더링·영속화 책임 분리 | 내장 React/TSX, `import`, Zustand 및 비공개 서비스 직접 접근. 이는 등록 가능한 외부 단일 JS 소스가 아님 |

두 구현은 작업 흐름과 책임 분리의 참고입니다. 외부 JS는 순수 JavaScript 한 파일과 `render.kind: 'component'`의 DOM 화면으로 옮깁니다. `import`/`require`/JSX, 내부 파일 경로, 임의의 `ctx.api.ai`·파일 읽기·호스트 재질 적용 API를 생성하지 않습니다. `ui-design`은 기존 내장 ID이므로 새 플러그인 ID로 사용하지 않습니다.

## 1. 한 파일 안에서 역할 나누기

정의와 상수 선언은 최상위에 둘 수 있습니다. 등록·활성화·실행·화면 수명을 구분하고 네트워크 요청·문서 변경·타이머를 최상위에서 실행하지 않습니다.

1. **모델/검증**: 입력·결과 스키마, 기본값, 길이·페이지 범위·자료 형식 검사. 손상된 저장값과 AI 응답을 검증합니다.
2. **저장소**: 플러그인 ID와 스키마 버전을 포함한 독립 키. 설정·작성 중 입력·초안·확정 결과·보관함을 구분합니다.
3. **작업 상태**: `idle/running/succeeded/failed/canceled`, 진행 건수, 현재 작업 ID, 요청 시작 문맥, AbortController와 마지막 정상 결과.
4. **작업 함수**: 생성·읽기·수정·취소·저장·명시적 적용을 UI와 분리합니다. 버튼과 `onAiTool`은 같은 함수를 호출합니다.
5. **뷰**: `mount(container, ctx)`에서 DOM·지역 스타일을 구성하고 상태를 렌더링합니다. 뷰 갱신이 AI 요청을 다시 시작하지 않게 합니다.
6. **등록**: 고유 ID, 버전, 설명, 필요한 `aiTools`, hooks, renderer를 담아 `registerPlugin`을 한 번 호출합니다. 실행 가능한 전체 소스는 200,000자 이내입니다.

단순 명령형 플러그인에는 보관함·확대 컨트롤을 억지로 추가하지 않습니다. 요구사항에 포함되지 않은 유료 AI·네트워크 기능도 추가하지 않습니다.

## 2. 화면은 독립된 작은 작업실로 구성

- **상단 문맥**: 이름, 목적, 현재 파일·페이지, 문서 없음/비활성 등 준비 상태.
- **01 입력·설정**: 요청 입력과 최소 옵션. 사용자 자료 입력이 필요한 경우 단일 파일과 폴더 선택을 구분하고 선택·분석·전송 시점을 설명합니다. 호스트의 파일 분석/범용 AI API는 현재 외부 JS에 공개되지 않았습니다. 브라우저가 지원하는 파일 선택·FileReader 외의 기능은 별도 API 확인이 필요합니다.
- **02 실행·상태**: 실행·중단, 현재 단계·건수·오류와 재시도 안내. 진행 중 중복 실행을 막고 취소는 실패와 다르게 표시합니다.
- **03 결과·미리보기**: 실제 반환된 결과와 빈 상태. 여러 결과는 제목·날짜·선택 표시로 구분합니다. 문서 변경·UI 적용을 수반하면 명시적 적용 전까지 초안으로 유지합니다.
- **결과 행동**: 다시 만들기와 디테일 수정은 구분합니다. 전자는 원래 요청, 후자는 현재 선택 초안과 추가 지시를 사용합니다. 지원 API가 없으면 실행 가능한 척하는 버튼을 만들지 않습니다.
- **보관함**: 이름·문서/페이지·생성 시각·요청과 결과를 저장하고 불러오기·이름 변경·삭제를 제공합니다. 생성 성공과 저장 실패를 구분하고 메모리의 정상 결과를 유지합니다.
- **표현**: 고유 루트 아래 지역 스타일, 한글 대체 글꼴, 실제 배경에 맞춘 글자 대비, 명시적 label, 포커스 표시, `role=status/alert`. 240/320/426/600px 패널과 별도 큰 미리보기에서 잘림·겹침을 피합니다.
- **스크롤**: flex 자식 `min-width:0; min-height:0`, 내용 `overflow:auto`, 버튼 줄바꿈. 고정 하단 버튼이 입력창과 결과를 덮지 않게 합니다. SVG가 있는 경우 벡터 글자·viewBox·전체 맞춤·수동 확대를 유지합니다.

## 3. 수명·비동기·문서 격리

- `onActivate`: 실행 상태와 설정을 준비합니다. 활성화 자체로 유료 요청을 시작하지 않습니다.
- `onRun`: 화면이 없는 플러그인은 본래 동작을 수행합니다. 화면형 플러그인은 사용자 실행·명시된 자동 모드에 따라 작업하며, 단순 패널 재열기로 비용을 발생시키지 않습니다.
- `onDocumentChange`: 파일·페이지 문맥을 갱신합니다. 자동 처리가 요청된 경우에만 미작성 대상에 실행하고 기존 결과를 재사용합니다. 강제 갱신은 별도 행동입니다.
- `onAiTool`: 선언한 도구명만 허용하고 인자를 재검증한 뒤 UI와 같은 작업 함수를 호출합니다. DOM이 열려 있어야 하는 구조라면 준비 전·닫힌 화면의 상태를 오류로 설명합니다. 가능하면 작업을 DOM과 독립시킵니다.
- `mount`의 반환 cleanup: 해당 뷰의 이벤트·구독·ResizeObserver·Object URL과 참조를 정리합니다. 여러 번 호출돼도 안전해야 합니다.
- `ctx.addCleanup`/`onDeactivate`: 플러그인의 모든 작업·타이머·구독을 정리합니다. 뷰 cleanup과 중복돼도 문제가 없어야 합니다.
- **패널 닫기와 비활성화는 별개**입니다. 기본은 뷰 종속 작업 취소입니다. 패널을 닫아도 계속되는 작업이 요구되면 상태·컨트롤러를 뷰 밖에 두고 재열기 시 진행률을 복원하되, 비활성화·문서 교체·중단에는 취소합니다. 결과를 보존하고 완료 결과를 사라진 DOM에 쓰지 않습니다.
- **늦은 응답 방지**: 시작 시 문서 식별·페이지·작업 ID를 캡처합니다. await 뒤 신호·작업 ID·문맥을 재검사합니다. 오래된 요청의 catch/finally가 새 작업의 busy/controller/result를 초기화하지 않게 합니다.
- 파일별 결과 키는 문서 식별과 페이지를 함께 사용합니다. 같은 이름의 다른 파일이 충돌하지 않도록 호스트에서 확인 가능한 경로/식별 범위를 사용하고, 식별할 수 없는 경우 한계를 밝힙니다. 다른 문서 결과를 현재 문서에 적용하지 않습니다.

## 4. 지원되는 API 안에서 구현

- 실제 본문: `ctx.api.document.getPageText`. 스캔에서 추출 실패하면 편집기 상태를 본문처럼 제시하지 않습니다. OCR API는 공개되지 않았습니다.
- 페이지 요약: `ctx.api.document.summarizePage`는 선택 제공자·모델을 사용하는 유료 요청입니다. 실행 전 전송 범위를 안내하고 사용자 요청 범위만 처리합니다. 범용 이미지 분석·임의 프롬프트 생성 API와 혼동하지 않습니다.
- 출처: 공개된 `lookupGlossaryTerm`/`summarizeGlossarySources`만 명세대로 사용합니다. 자료의 지시는 실행하지 않습니다.
- 재질: `material_get`/`material_apply` 등은 내장 `ui-design`의 AI 도구명입니다. 외부 JS에 `ctx.api.material` 또는 플러그인 간 도구 호출 API가 생긴 것이 아닙니다. 새 플러그인은 자체 화면의 지역 재질을 다루고, 호스트 전체 적용 요구는 공개 API 확장 필요를 설명합니다.
- API 키를 직접 읽거나 하드코딩하지 않습니다. 첨부 자료 전송은 사용자 요청·허용 범위와 실제 지원 경로를 확인합니다. 설치/초안/활성화/실행/적용/파일 저장은 서로 다른 결과로 보고합니다.

## 5. 기존 코드 수정·산출물 확인

기존 코드의 ID, 저장 스키마·정상 결과·사용자 수정본을 보존합니다. 데이터 형식을 변경할 때는 버전 확인·검증·명시적 마이그레이션을 제공하고 사용자 편집 소스를 자동 덮어쓰지 않습니다. 다른 플러그인의 ID·저장 키·스타일을 재사용하지 않습니다.

외부 AI는 요구를 구현한 전체 교체용 JS 하나와 짧은 사용법을 반환합니다. 구현·미지원·검증하지 않은 사항을 구분합니다. 다음 시나리오를 확인하거나 실행 환경이 없어 확인하지 못했다고 밝힙니다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 등록 → 활성화 → 실행 → 패널 닫기/재열기 | 중복 작업·구독 없이 상태 복원, 입력과 정상 결과 보존 |
| 우클릭 비활성화 → 재활성화, 앱 재시작 | 자원 해제 후 독립 실행, 저장된 결과 복원 |
| 문서/페이지 전환 중 완료·취소·빠른 재실행 | 다른 문서 오염 없음, 늦은 응답이 새 작업을 덮지 않음 |
| 무문서·빈 입력·잘못된 응답·저장 공간 부족 | 명확한 상태·복구 행동, 마지막 정상 결과 보존 |
| 초안 선택·다시 만들기·디테일 수정·적용/복구 | 선택 결과가 해당 대상에 반영되고 적용 전 호스트는 보존 |
| 좁은 패널·키보드·밝은/어두운 배경 | 스크롤 가능, 입력·버튼·한글 가독성 유지 |

사용자의 요구에 없는 기능은 위 표에서 해당 없음으로 처리합니다. 실제로 하지 않은 자동 검증·설치·외부 API 성공을 주장하지 않습니다.
