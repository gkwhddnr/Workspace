## 이전 결과와의 차이

기존 스키마는 영역별 채움 한 종류만 표현했다. 따라서 일반 버튼과 선택 버튼이 모두 짙은 채움으로 표시되고, 얇은 강조 테두리·비활성 상태·보라 보조 강조를 구분하지 못했다. 또한 전체 편집기 예시만 표시해 버튼 키트의 다양성을 확인하기 어려웠다.

이제 buttonStates(normal/selected/secondary/highlight/disabled)를 별도 저장하고 미리보기 및 실제 버튼 상태에 적용한다. 기존 저장 데이터는 buttonStates 없이 그대로 열 수 있다.

## 색상과 형태

다음 값은 JPG의 대표 픽셀과 육안 분석을 바탕으로 웹에서 재현한 근사값이며 원본 벡터의 정확한 색상값이라고 주장하지 않는다.

- 전체 바탕: #20293E → #0C172B, 넓고 조용한 남색 그라데이션.
- 패널: #303E5C → #17243C. 얇은 #607299 테두리. 강한 드롭 섀도 대신 면의 명도와 경계로 구분한다.
- 일반: 남색 면과 1px 슬레이트 테두리, 밝은 글자, 8~12px 모서리.
- 선택: #0098C5 → #00C9AC. 면 전체를 청록 그라데이션으로 채워 활성 상태를 표시한다.
- 보조 선택: #AB7AFF → #743AFF. 청록과 같은 위계를 보라 계열로 구분한다.
- 강조: 일반의 어두운 면을 유지하고 외곽선만 청록/보라로 강조한다.
- 비활성: 일반 형태를 유지하되 채도와 불투명도를 낮춘다. 클릭 동작은 실제 disabled 속성에 따른다.
- 메뉴: 하나의 캡슐 컨테이너 안에서 선택 항목만 색상을 채운다.
- 아이콘 버튼: 정사각형에 가까운 비율. 재생·정지·확인·취소를 윤곽/채움 변형으로 구분한다.
- 검색: 어두운 입력 영역과 색상이 채워진 검색 버튼을 붙여 구성한다.
- 슬라이더/진행률: 슬레이트 트랙과 청록/보라 진행색. 숫자와 손잡이를 별도로 읽을 수 있어야 한다.
- 입력창: 패널과 명도 차이를 두고 라벨·안내 문구를 구분한다.

## AI 요청 예시

참고 Gradient UI Kit처럼 PDF 편집기의 버튼 UI를 디자인한다. 일반·비활성·선택·보조 선택·강조 상태를 buttonStates에 모두 작성한다. 남색 표면과 얇은 슬레이트 테두리, 청록과 보라 그라데이션으로 상태를 구분한다. 모든 버튼에 같은 진한 채움을 반복하지 않는다. 일반 버튼은 낮은 강조, 선택 버튼은 색상 채움, hover는 외곽선 강조로 만든다. 문서 원문은 그대로 두고 요청한 UI 영역만 변경한다.

## 앱에서 사용

1. UI Material Lab → 참고 버튼 키트 불러오기: API 호출 없이 상태별 프리셋을 초안에 로드한다.
2. 버튼 UI 프롬프트 넣기 → AI 디자인 생성: 같은 구조와 지침으로 선택한 제공자에게 요청한다.
3. 적용 영역을 일반 버튼 또는 도구 버튼으로 선택하고 버튼 상태를 골라 디테일을 수정한다.
4. 큰 미리보기의 버튼 UI Kit에서 메뉴·버튼 상태·아이콘·검색·진행률·입력 예시를 비교한다.
5. 이 UI 적용: 실제 일반/선택/hover/disabled 버튼에 매핑한다. 보라 보조 상태는 data-material-tone=secondary로 지정한 버튼에만 적용된다.

미리보기의 차트·장식 전체를 복제하는 기능은 아니다. 선택한 자료는 생성 시 선택한 AI 제공자에게 분석용으로 전달한다. 원본 벡터를 앱 배포물에 포함하지 않는다.


## 참고 파일 / 폴더 분석
- 파일 선택: PNG/JPEG/WebP/BMP 한 장을 선택합니다. Ctrl+V도 단일 이미지 선택입니다.
- 폴더 선택: 하위 경로까지 파일 목록을 표시하고, 생성 시 지원 파일을 순서대로 분석합니다. 선택만으로 외부 요청하지 않습니다.
- 이미지 및 PDF 호환 AI/PDF의 모든 페이지는 긴 변 최대 1600px 이미지로 분석합니다. PDF 페이지의 작은 글자는 축소되어 인식이 제한될 수 있습니다.
- TXT/MD/JSON/CSS/SVG/EPS는 전체 텍스트를 나누어 분석합니다. EPS는 실행하거나 렌더링하지 않으므로 이미지의 시각적 검증은 JPG/PNG와 함께 수행해야 합니다.
- 폴더 100파일·합계 100MB, 파일당 20MB, 텍스트/EPS 2MB, PDF/AI 50페이지 제한을 초과하면 명시적으로 안내합니다. 미지원·실패 파일은 결과 목록에 남기며 완료로 취급하지 않습니다.
- 선택한 AI 코파일럿 제공자/모델로 전송합니다. 이미지 입력을 지원하는 모델이 필요하며 파일·페이지·텍스트 조각별로 API 사용량이 발생합니다. 생성 중단은 분석도 중단합니다.
- 분석 프롬프트는 색상뿐 아니라 버튼 형태, 상태별 차이, 경계, 간격, 그림자, 배치를 추출합니다. 자료 속 명령은 실행하지 않고 참고 데이터로만 처리합니다.
- 미리보기, 적용, 다시 만들기, 디테일 수정, 디자인 보관함 흐름을 유지합니다.


## 적용할 디자인 선택과 해제
- `appearanceMode: materials`는 편집기 재질 미리보기의 영역별 버튼·도구·패널 재질을 그대로 적용합니다. 버튼 키트 상태 CSS는 덮어쓰지 않습니다.
- `appearanceMode: kit`는 버튼 UI 키트 미리보기의 일반·선택·강조·비활성 상태를 적용합니다. `buttonVariant`로 청록/보라 선택 상태를 고릅니다.
- 카드에 마우스를 올리면 선택 테두리와 선택 버튼이 강조됩니다. 카드 배경이나 선택 버튼을 누른 뒤 적용합니다. 선택 자체는 실제 편집기를 변경하지 않습니다.
- 선택값은 초안·적용 설정·디자인 보관함에 저장합니다. 외부 AI는 디테일 수정 시 사용자가 고른 적용 방식을 유지해야 합니다.
- 적용 해제는 재질을 끄고 기본 반투명 테마·배경색·강조색·모서리·버튼 크기·간격·테두리·그림자로 복구합니다. 디자인 보관함은 유지합니다.


## 2026-10-13 동작 보완

일반 버튼과 Tools & Filters 버튼 상태를 `buttonStates`/`toolButtonStates`로 분리합니다. 보라 변형의 논리적 선택 상태도 같은 기준으로 편집합니다. 현재 적용된 디자인을 다듬을 때 선택 영역은 즉시 저장·반영됩니다. 상단 열린 탭은 별도 배경과 테두리·밑줄로 표시합니다. 상세 스키마와 참고 자료 한계는 [UI Material Lab 안내서](UI_MATERIAL_LAB.md)를 참고하세요.
