# Editorial Diagram 전용 AI 지침

업데이트: 2026-10-13 · 예제 JS 1.8.1

이 지침은 페이지 본문 요약과 다이어그램·보충설명 작성용입니다. JS 플러그인 제작은 [API 명세](EXTERNAL_AI_PLUGIN_API.md), 편집기 UI 재질은 [Material Lab 안내](UI_MATERIAL_LAB.md)를 사용합니다.

## Editorial Diagram 페이지 요약 작성 규칙

- 기존 `editorial-diagram` ID, 에디토리얼 SVG 디자인, 흐름 입력, 실행 버튼, SVG 복사·다운로드 구조를 유지합니다.
- 각 페이지 원문을 읽어 핵심 개념과 관계를 짧은 제목, 요약, `A -> B -> C` 흐름으로 작성합니다. 인과·순서가 없는 내용에는 임의 관계를 만들지 말고 분기나 독립된 줄로 표현합니다. 원문에 없는 내용을 보충하거나 기본 예시를 페이지 요약으로 저장하지 않습니다.
- 코파일럿은 `read_page({page})`로 대상 페이지를 읽고 `plugin_use({id:"editorial-diagram",tool:"create_diagram",input:{page,title,summary,flow}})`를 호출합니다. `summary`는 2,000자, `title`은 120자, `flow`는 12,000자, 노드는 40개 이내입니다.
- 전체 파일 요청은 1~numPages의 각 페이지를 처리하고 `get_page_diagrams` 결과로 저장된 페이지를 확인합니다. 읽을 수 없는 페이지는 미작성 상태와 이유를 보고합니다. 사용자가 허용한 ‘페이지 자동’ 모드에서는 이동한 미작성 페이지의 본문을 요약하며, OFF 상태에서는 자동 API 요청을 보내지 않습니다. 전체 페이지 요약은 사용자가 버튼을 눌렀을 때 순차 실행하고 중단 버튼을 제공합니다.
- 페이지 내용 요약에는 `summarize_page` AI 공개 기능을 제공하고 내부에서 `ctx.api.document.summarizePage`를 호출합니다. `create_diagram`은 사용자가 직접 작성했거나 외부 AI가 제공한 제목·요약·흐름을 저장하는 기능으로 유지합니다. 확대/축소·맞춤·SVG 다운로드/복사도 유지합니다.
- JS 플러그인은 `ctx.api.document.getPageText`로 실제 본문을 읽거나 `ctx.api.document.summarizePage`로 요약을 생성할 수 있습니다. `ctx.api.editor`에 텍스트 추출 메서드나 AI 호출 메서드가 있다고 추측하지 않습니다. 외부 AI가 원문을 이미 제공받았다면 페이지 번호와 요약 흐름을 전달합니다.
- 결과는 파일 경로/이름과 문서 데이터 지문을 기준으로 구분하여 페이지별로 localStorage에 보관합니다. 페이지 이동·패널 재열기·앱 재시작 후 저장된 요약을 복원하고, 미작성 페이지에는 이전 페이지의 결과를 재사용하지 않습니다.
- UI 준비 전 AI 입력은 보관하거나 호스트의 mount 완료 대기를 사용합니다. 기능 실행 결과에 저장 여부와 페이지를 반환하며 SVG 미리보기를 PDF 삽입으로 표현하지 않습니다.


### 저장된 요약 보호와 명시적인 업데이트

전체 페이지 요약과 페이지 자동은 저장된 페이지를 건너뛰고 기존 결과를 유지합니다. 재요약은 별도의 ‘현재 페이지 요약 업데이트’ 버튼으로만 요청합니다. `ctx.api.document.summarizePage(page, signal, { refresh: true })`는 메모리 캐시를 우회하여 AI에 다시 요청합니다(API 비용 발생). 성공한 결과만 저장된 페이지와 교체하고, 실패·취소 시 기존 요약을 삭제하지 않습니다. 기본 호출은 캐시를 재사용합니다.


### 다이어그램 연결선 가독성

서로 연결되지 않은 개념 그룹은 독립 영역으로 배치하고 그룹 사이 여백을 확보합니다. 각 그룹 내부는 부모·자식의 위치를 기준으로 노드 순서를 정렬해 교차를 줄입니다. 여러 화살표의 출발/도착 지점을 분산하고, 중간 열을 건너뛰거나 순환하는 연결은 노드 밖의 별도 경로로 보냅니다. 연결을 삭제하거나 의미를 바꿔 교차를 숨기지 않습니다. 복잡한 그래프는 교차를 완전히 제거하지 못할 수 있습니다.


### 용어·기법·법칙의 보충설명

페이지 요약 결과와 Editorial Diagram의 `create_diagram`에 선택 필드 `glossary: [{term, explanation}]`를 사용할 수 있습니다. 원문에 등장하는 생소한 용어·기법·법칙·관계명을 최대 8개 선정하고, 각 용어 80자/설명 800자 이내로 뜻과 해당 문맥의 역할을 한국어로 설명합니다. 예: `{term:"Paid-by", explanation:"이 문맥에서 결제가 어떤 결제 수단 또는 주체와 연결되는지를 나타내는 관계명입니다. 정확한 방향과 의미는 연결된 클래스와 문맥을 함께 확인해야 합니다."}`. 원문 요약과 AI의 일반 지식 보충설명을 구분하며 불확실한 뜻을 단정하지 않습니다. 다이어그램 아래의 접근 가능한 details/summary에서 클릭·키보드로 펼치고, 페이지별로 영구 저장합니다. 기존 요약에 설명이 없더라도 자동 재요청하지 않고 명시적 업데이트 시에만 추가합니다.


### 개념 역할에 따른 배치

단순 계층은 전체 구조로, 다중 부모·순환이 많은 네트워크는 기준 개념별 관계 패널로 배치합니다. 관계 패널에서 반복된 대상은 ‘동일 개념 참조’임을 표시하고 모든 연결을 보존합니다. ‘포함한다·설명한다’ 등 관계 표현은 출발/도착이 명확할 때 화살표 라벨로 표현하고, 여러 출발/도착이 섞이면 임의로 짝짓지 않습니다. 사용자가 전체 구조/관계별 분리를 선택할 수 있도록 합니다.


## PDF별 요약 보관

실제 파일 경로가 있는 PDF의 요약·다이어그램·뜻풀이는 정규화된 경로별로 앱 로컬 저장소에 보관합니다. 같은 경로의 파일을 저장 후 다시 열어도 복원하며 자동으로 재요약하지 않습니다. 경로가 없는 업로드는 내용 해시로 구분합니다. PDF 자체에 삽입되는 데이터는 아니며 파일 이동이나 다른 컴퓨터로의 자동 이전은 지원하지 않습니다. 같은 경로에 다른 PDF를 덮어쓴 경우에는 사용자가 요약 업데이트로 갱신해야 합니다.


## 핵심 요약·반응형 배치·웹 자료

핵심 요약은 편집란과 별도로 다이어그램 앞에 표시합니다. 관계별 패널은 폭 740px 이상 또는 폭 540px/높이 680px 이상에서 2열로 전환하고, 작아지면 1열로 복원하며 자동 맞춤합니다. 용어의 ‘웹 보충설명 찾기’는 한국어/영어 Wikipedia의 정확한 문서명·리다이렉트를 조회하고 실제 발췌문과 출처 URL을 페이지별로 저장합니다. 관련 문서를 찾지 못하면 추측 출처를 생성하지 않습니다. 출처는 웹 서퍼 탭으로 열립니다. API: `ctx.api.document.lookupGlossaryTerm(term, signal?)`. 웹 요청에는 해당 용어만 전달합니다.


## 웹 조회 버튼의 주제 제한

파일명(확장자 제외)을 문서의 주제로 사용하고, 페이지 문맥에서 그 주제와 직접 관련된 전문용어·기법·법칙에만 `topicRelated:true`를 지정합니다. 일반 단어·예시 이름·단순 관계 동사·불확실한 용어는 false로 처리합니다. 웹 조회 버튼은 해당 파일의 주제 판정이 있는 용어에만 표시합니다. 기존 저장 설명에 판정이 없으면 버튼을 숨기며 ‘현재 페이지 요약 업데이트’로 새 판정을 받을 수 있습니다. 뜻풀이 자체는 계속 표시합니다.

### 웹 뜻풀이의 문맥 확인
강화학습 문서의 GPI는 Generalized Policy Iteration(일반화된 정책 반복)을 의미합니다. 약어만으로 다른 분야의 의미를 선택하지 않습니다. 웹 조회는 동음이의어 문서를 제외하며, 의미를 확정할 수 없는 짧은 약어는 발췌를 제공하지 않습니다. 기존 웹 발췌는 새 조회로 교체해야 표시됩니다. 추가 AI 요청은 사용하지 않습니다.

### 여러 웹 출처
웹 보충설명은 한국어·영어 Wikipedia와 Crossref 학술 문헌을 함께 조회하며 중복을 제외한 최대 4개 출처를 번호와 링크로 표시·저장합니다. 문헌 제목에 판별된 용어가 있는 자료만 포함합니다. 서지정보는 웹 발췌와 구분하고 논문 본문을 읽었다고 주장하지 않습니다. 출처가 1개뿐이면 그대로 표시하며 개수를 채우기 위해 관련 없는 출처를 추가하지 않습니다. 각 링크는 웹 서퍼로 엽니다. 추가 AI 요청은 없습니다.

- 강화학습 용어 웹 조회는 제목 일치 외에 백과사전 본문 또는 문헌 제목·초록의 강화학습 문맥을 확인합니다. SARSA 사전 항목과 분야가 확인되지 않은 자료는 제외하며, 기존 출처는 다시 조회해야 표시됩니다. 자료가 부족하면 출처 개수를 채우지 않습니다.

### 코드 페이지 실행 원리
코드·의사코드는 입력/전제, 초기화, 변수 역할, 조건의 참·거짓 분기, 상태 갱신, 반복·종료, 반환 결과를 실제 코드 순서에 맞춰 다이어그램으로 설명합니다. 독립 함수와 데이터 흐름은 분리하고 작은 실행 예를 핵심 요약에 포함합니다. 잘린 코드는 추측하지 않습니다. 기존 저장 요약은 자동 덮어쓰지 않으므로 ‘현재 페이지 요약 업데이트’를 사용합니다.

### 출처를 읽고 보충내용 정리
조회 후 이 버튼을 누르면 실제 확보한 발췌·초록을 선택한 AI 제공자에게 전달해 용어 원리·적용 예·주의점을 정리합니다. API 비용이 발생합니다. 각 근거는 [1] 등의 출처 번호를 유지하며 전체 원문을 읽었다고 주장하지 않습니다. 서지정보만 있는 출처는 요약에 사용하지 않습니다. 정리 내용은 페이지별 저장되며 출처를 다시 조회하면 이전 정리 내용은 지워집니다.

웹 출처는 문서 주제와 뜻풀이 문맥이 확인될 때만 포함합니다. 병렬프로그래밍의 displacement에는 MPI·병렬 처리·메모리/버퍼 주소 문맥이 필요하며 이주·강제이주·수학적 보간 자료는 포함하지 않습니다. 주제가 판별되지 않으면 파일명 주제와 맞는 근거가 없는 자료를 제외합니다. 이 기준은 출처 조회와 보충요약에 모두 적용하며, 이전 기준으로 저장된 출처/보충요약은 다시 조회할 때까지 표시하지 않습니다.
